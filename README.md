# 反向💣扫雷 · Reverse Minesweeper

> 普通扫雷是「棋盘上埋好了雷，你去推理它在哪」；
> **反向扫雷**是「棋盘上的数字已经给你了，你来把雷埋回去」。

纯静态单页小游戏：原生 HTML + CSS + JavaScript，**无构建、无依赖、无网络请求**，用浏览器打开 `index.html` 即可游玩。

| 项目 | 值 |
| --- | --- |
| 当前版本 | **v1.2.1** |
| 运行形态 | 纯静态网页（浏览器直接打开即可，不需要安装或构建） |
| 存档 schema | v1（`RM.SAVE_SCHEMA` / `Store.schema`） |
| 地雷图鉴 | **22 种**，分 **5 个系列** |
| 成就 | **45 个**（7 大类，其中 14 个隐藏成就） |
| 作者 | L1Nzy · lin060911@qq.com · © 2026 |

## 1. 玩法说明

### 1.1 核心规则

- **目标**：在棋盘上放置规定数量的地雷（普通雷 + 特殊雷），使得棋盘上每个格子显示的数字，**恰好等于**它周围（或该雷种特定规则下）所有地雷对它的**总影响值**。
- **操作**：点选放置、拖拽放置、右键（手机端长按）删除。
- **胜利条件**：所有地雷放完，且棋盘数字与地雷影响完全匹配（棋盘上都是 🟩）。
- **题目怎么来的**：每局由程序随机决定雷种与落点，再反算出每个格子的目标影响值（`G.tar`）当作题面；你看到的数字就是"答案的影响值"，要反推布雷位置。地雷落点唯一性不做保证——只要放满规定数量、且影响值完全吻合即算通关。

### 1.2 操作方式

| 入口 | 位置 | 说明 |
| --- | --- | --- |
| 新游戏 | 主按钮条 | 重开一局（预设难度会先进入"准备好了吗"确认卡片） |
| 清空放置 | 主按钮条 | 清掉本局已放置的所有地雷 |
| 教学🧐 | 主按钮条 | 新手引导与基础挑战 |
| 难度🕹️ | 主按钮条 | 简单/中等/困难/地狱/脑王/自由 + 系列开关 |
| 🧭信息 | 左侧栏 | 规则信息、炸弹信息（各系列地雷图鉴与挑战入口） |
| 📝记录 | 左侧栏 | 成就解锁进度 + 成绩记录 |
| ✍️创造 | 右侧栏 | 自己出题 + 题库码分享/导入 |
| ⚙️设置 | 右侧栏 | 音量、地块提示、放置模式、存档管理 |

放置方式支持两种（可在设置里切换，存于 `placeMode_v1`）：**拖拽**（把地雷拖到棋盘松手）与**点选**（先点地雷选中，再点棋盘放置）。

### 1.3 地块状态解读

游戏会实时按当前布雷情况给每个格子着色：

| 颜色 | 含义 |
| --- | --- |
| 🟩 合适 | 当前影响值 **等于** 显示数字（正确） |
| 🟨 偏低 | 当前影响值 **小于** 显示数字（还需在周围加雷） |
| 🟥 偏高 | 当前影响值 **大于** 显示数字（需要减少影响） |

设置里可开启「🔺 实时影响值」：影响值不为 0 且不等于题目数字的地块，会在右下角显示它当前的实时影响值。

### 1.4 难度、参数与解锁链

四个可调参数：**棋盘大小**（8–20）、**总地雷数**（2–24）、**特殊雷种类**（0–22）、**特殊雷数量**（0–99，会自动收敛为 ≤ 总雷数，且种类数 ≤ 特殊雷数量）。

预设难度（大小 / 总雷数 / 特殊雷种类 / 特殊雷数量）：

| 难度 | 大小 | 总雷数 | 特殊雷种类 | 特殊雷数量 |
| --- | --- | --- | --- | --- |
| 😎 简单 | 8×8 | 4 | 2 | 3 |
| 😮 中等 | 10×10 | 8 | 4 | 6 |
| 😤 困难 | 12×12 | 12 | 6 | 9 |
| 👿 地狱 | 14×14 | 14 | 8 | 12 |
| 🤯 脑王 | 12×12 | 16 | 12 | 14 |
| 🔧 自由 | 10×10 | 6 | 3 | 3（标准参数，可自由修改） |

**解锁链**：

1. 出生即玩 **基础挑战**（5 关），通关后解锁各系列挑战入口。
2. 每个 **系列挑战**（5 关）通关后，解锁该系列地雷，并可在「难度🕹️」里打开对应的系列开关。
3. **简单 / 中等 / 困难**：需开启 **≥3 个**系列开关。
4. **地狱 👿**：需开启 **全部 5 个**系列开关。
5. **脑王 🤯**：地狱难度通关 **≥10 次** + 全部 5 个系列开关。

🔧 **自由模式**不记录成绩、不显示计时器。基础系列（basic）始终开启，其余四个系列需要各自通关对应挑战才能解锁。

### 1.6 创造模式

- 自定义棋盘：边长 4–20，总格数上限 400（改一边另一边会自动收敛）。
- 自己摆好地雷后生成 **题库码**，可一键复制分享（复制内容自带一句分享文案）。
- 把别人的题库码粘贴回来即可复原题目并挑战（`diff` 置空、正常计时）。
- 成就方面：**出题**（每次生成题库码）计入「创造模式」类成就；**破解他人分享的题目**并通关计入分享类成就。注意自定义 / 分享题目**不写入成绩记录**（`saveRec()` 在 `diff` 为空时直接返回）。

### 1.7 成就与成绩

- 共 **45 个成就**，分 7 大类：新手村 3、预设难度 7、系列道具 5、速通系列 6、创造模式 5、累计通关 5、隐藏 **14**。
- 成就按 `once`（一次性）/ `count`（计数）/ `special`（通关时条件判定）/ `time`（速通时限）四类定义。
- **隐藏成就**在解锁前只显示 🔒 与"隐藏成就，达成后揭晓"，不剧透名称与条件。
- 左侧「📝记录」栏（成就侧栏）同时展示成绩记录：各难度的最快用时与累计通关次数。

> 具体成就清单与达成条件请直接在游戏内「📝记录」栏查看，本文不列出，避免剧透。

### 1.8 设置、存档与音频

**设置（✍️/⚙️ 右侧栏）**

- 🎵 背景音乐音量、💥 游戏音效音量：持久化在 `mineSoundSettings`。
- 🔺 实时影响值开关：持久化在 `mineInfluenceHint`。
- 放置模式（拖拽 / 点选）：持久化在 `placeMode_v1`。

**存档管理**

- 存储层优先使用 `localStorage`，完全不可用时自动降级为**内存 Map**（本次会话有效，页面关闭即失）。设置栏会显示当前实际使用的后端。
- 📤 导出：生成 JSON 文件（`app` / `schema` / `exportedAt` / `data`），文件名形如 `反向扫雷-存档-YYYYMMDD.json`。
- 📥 导入：先弹出对比框——**覆盖 / 合并 / 取消** 三选一，并用表格列出"当前存档 / 覆盖后 / 合并后"的逐项差异（标红＝将丢失、标绿＝将新增，成就行还会用 `(+N)` 标出新增数量）。
- 导入前会自动留一份当前存档快照，设置栏可「↩️ 撤销上次导入」回退。
- 🗑️ 清空存档：清掉全部受管键（成绩、成就、系列解锁等），不可撤销。
- 存档写入时附带简易校验和（`__sig`），用于发现"被手工改过"，不做安全对抗。

**音频**

- 全部音效与 8-bit 背景音乐由 **WebAudio 实时合成**，项目内没有任何音频素材文件。
- 全局只创建 **一个 `AudioContext`**：音效与 BGM 各挂一条独立 `Gain` 总线，避免密集解锁成就时耗尽浏览器允许的 AudioContext 数量导致静音。

### 2.3 脚本加载顺序

`index.html` 底部按文件名序号顺序加载 16 个脚本，**顺序即依赖关系，不可调换**：

```
00-core → 01-storage → 02-audio → 03-timer → 04-mines → 05-generator
→ 06-render → 07-board → 08-ui → 09-tutorial → 10-game → 11-create
→ 12-settings → 13-achievements → 14-bgeffects → 15-boot
```

几个关键的先后关系：

- `00-core.js` 提供 `RM`、`Store` 之外的常量与状态，其它模块在顶层就会读取它们。
- `10-game.js` 定义了 `newGame` / `fullReset`，并给 `#reset`、`#clear` 挂上点击处理。
- `12-settings.js` 暴露 `window._gameNS`，`13-achievements.js` 通过它取原始函数来包装（也因此 12 必须在 13 之前）。
- `13-achievements.js` 在 `10-game.js` 之后接管 `#reset` 的点击计数（成就「退！退！退！」）。
- `15-boot.js` 最后运行：自检必需模块（`REQUIRED` 列表），缺失时提示"部分模块未加载"，并完成存档 UI 接线。

## 3. 架构与开发约定

### 3.1 运行形态

- 纯静态、零依赖、零构建：没有 `package.json`、没有打包器、没有 npm 包，浏览器直接解析源码。
- 所有脚本都是传统 `<script src>`（**非 ES Module**），共享同一个全局作用域，模块之间通过全局函数 / 全局变量通信。
- 所有 DOM 都在 `index.html` 里静态定义（`style="display:none"` 预置隐藏），运行时只做显隐切换与内容填充；仅确认框、导入框、成就弹窗、漂浮特效等少量元素是运行时创建的。

### 3.2 关键全局对象

| 名称 | 来源 | 作用 |
| --- | --- | --- |
| `RM` | 00-core | 命名空间：`RM.VERSION`、`RM.SAVE_SCHEMA`、`RM.warn/onError`（最多留 50 条错误）、`RM.toast()`、`RM.timer` |

### 3.3 模块风格与 use strict 约定

项目里混用三种模块写法，改动时请保持一致：

| 写法 | 文件 |
| --- | --- |
| IIFE + `"use strict"` | 01、02、12、13、15 |
| IIFE（非严格） | 14 |
| 顶层 `function` / `let` / `const`（全局脚本） | 00、03、04、05、06、07、08、09、10、11 |

- **`00-core.js` 刻意不使用 `"use strict"`**：按文件注释说明，项目里存在 `newGame = function(){}`、`fullReset = function(){}` 这类顶层重新赋值，为了让钩子包装行为与代码拆分前完全一致，保持宽松模式。
- 全局脚本里声明的东西（如 `newGame`、`fullReset`、`drop`、`del`、`clearAll`）都是**全局标识符**，成就系统靠重新赋值它们来挂钩子——新增同名局部变量会破坏钩子链。

### 3.4 钩子（installHooks）机制

`13-achievements.js` 的 `installHooks()` 是整个成就系统的装配点，用 `window._achHooksInstalled` 防止重复安装。它通过**包装全局函数**来统计玩家行为：

- 包装目标包括 `window.unlockSeries`、`onTutorialWin`、`del`、`clearAll`、`drop`、`fullReset`、`startTi`、`stopTi`、`generatePuzzleCode`、`applyPuzzleCode`，以及直接接管 `#reset` 按钮的点击。
- 典型写法：先取原函数（`var _oDel = window.del`），再用同名新函数替换，在新函数里**先完成自己的记账，再调用原函数**并透传返回值。
- 因此修改这些被包装函数的**名字、签名或调用路径**时，要同步检查成就系统的钩子，否则会出现漏统计或重复统计。

### 3.5 样式约定

- **所有样式集中在 `style.css`，不在 JS 里注入 `<style>`**：需要新增的样式请写进样式表对应分区。
- 弹窗统一使用 `.auto-modal-overlay` + `.auto-modal` 体系（`index.html` 里的欢迎框、教学框、各类锁定框都是这个结构）：`.icon` / `h2` / `p` / `button` 由基础规则统一控制，宽度 520px、`top: 40%`、100px 浮动大图标、32px 标题、蓝色胶囊按钮；窄屏（≤700px）自适应为 88% 宽、最大 340px。
- 运行时创建的两个弹窗也复用同一套外观，只补自定义部分：
  - 通用确认框：`08-ui.js` 的 `openConfirmModal({icon,title,body,buttons,onAction})`；
  - 存档导入框：`15-boot.js` 的 `ensureModal()` / `openImportModal()`。
  - 二者共用 `.rm-btn-row` + `.rm-btn` 按钮行，颜色类 `.rm-btn-primary`（蓝）/ `.rm-btn-danger`（红·覆盖）/ `.rm-btn-merge`（绿·合并）/ `.rm-btn-cancel`（灰·取消）。
- `.rm-*` 前缀是本项目运行时追加功能使用的类名（`.rm-toast`、`.rm-acc-*` 信息栏折叠、`.rm-cmp` 对比表、`.rm-mode-box` 说明块等）。
- 改 `.auto-modal` 基础规则会**同时影响所有弹窗**，动手前先确认影响面。

### 3.6 存档约定

托管键（会被导出、导入、清空）：

- 白名单：`mineLastTimes`、`mineRecords`、`mineWins`、`brainUnlockedNotified`、`brainCleared`、`seriesState`、`seriesUnlocked`、`tutorialStep`、`tutorialCompleted`、`placeMode_v1`、`mineInfluenceHint`、`mineSoundSettings`、`welcomeLastShown`、`hasVisitedBefore`、`achievementState_v1`、`rmSchemaVersion`。
- 前缀匹配：`tutorial_`（各系列挑战进度）、`mine`（图鉴相关）、`rm`（版本等）。
- **新增需要持久化的键，必须同步更新 `01-storage.js` 里的 `KEY_WHITELIST` 或前缀**，否则导出 / 导入 / 清空存档都会漏掉它。

辅助键（不参与导出与覆盖清空）：后缀 `__bak`（备份）、`__pre`（导入前快照）、`__sig`（校验和），以及 `rmPreImportAt`、`rmPreImportISO`。

存档 schema 由 `RM.SAVE_SCHEMA` / `Store.schema` 定义（当前为 **1**），导入更高版本的文件会给出"来自更新的版本"警告。localStorage 不可用时自动降级到内存后端，功能可用但**不持久**。

### 3.7 改代码注意事项

1. **不要改 `index.html` 底部脚本的顺序与文件名**：序号即加载顺序，调换会因全局依赖未就绪而报错；新模块请继续按序号命名（当前 00–15）。
2. 模块在**顶层**就会读取全局依赖（例如 `08-ui.js` 顶层直接给按钮挂 `onclick` 并调用 `AudioFX`），所以新代码不要假设"后面加载的模块能用"。
3. 被成就系统包装的全局函数（`newGame`/`fullReset`/`drop`/`del`/`clearAll`/`startTi`/`stopTi`/`unlockSeries`/`onTutorialWin`）改名或改调用路径时，同步检查 `installHooks()`。
4. 严格模式模块里不要对**未声明的标识符**赋值（会抛 `ReferenceError`）；这类全局重赋值请沿用非严格的全局脚本写法。
5. 新增界面文本请保持中文风格与现有 emoji 文案一致；弹窗、提示优先复用 `RM.toast()` 与 `openConfirmModal()`，不要引入 `window.alert`（存档相关的破坏性操作除外，现有实现已固定）。
6. 所有持久化都走 `Store`，不要在业务代码里直接 `localStorage.setItem`，否则会绕过校验和、备份与导出机制。
